# AGENTS.md

## Cursor Cloud specific instructions

### What this repo is
`Xal's Path` is a single-product **Unity game** (not a monorepo). It is a story-driven
clicker/idle mobile game written in C#, pinned to **Unity 2020.3.16f1**
(`ProjectSettings/ProjectVersion.txt`). Targets are iOS & Android. There is **no backend,
no database, no docker-compose, no Makefile, and no Node/pip/go dependency manifest** — all
dependencies are Unity packages resolved from `Packages/manifest.json` +
`Packages/packages-lock.json` the first time the Editor opens the project.

### Toolchain already provisioned in the VM snapshot
- Unity Editor 2020.3.16f1 (Linux) is installed at **`/opt/unity/Editor/Unity`** (~5.4 GB).
- System runtime libraries Unity needs (GTK/X libs, `xvfb`, `libicu74`, `mono`, etc.) are
  installed. Run the Editor headless via `xvfb-run -a`.
- If `/opt/unity/Editor/Unity` is ever missing (snapshot not restored), re-download the exact
  build: `curl -L -o Unity.tar.xz https://download.unity3d.com/download_unity/049d6eca3c44/LinuxEditorInstaller/Unity.tar.xz`
  then `tar -xJf Unity.tar.xz -C /opt/unity` (the tarball is ~2.6 GB).

### Licensing is required and is the main gotcha
The Editor cannot compile, build, run, or open the project without an **activated Unity
license**. Without credentials every headless run ends with:
`Failed to activate/update license Missing or bad username or password`.

- The modern `LicensingClient` crashes on this image (a .NET globalization/ICU issue,
  "Couldn't find a valid ICU package"), but Unity **falls back to Legacy licensing, which
  works** (it successfully generates `.alf` activation files and accepts `-username/-password`).
  You can usually ignore the LicensingClient stack trace in the log; look for the Legacy
  fallback line right after it. Setting `DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=1` may quiet the
  crash but is not required.
- Activation needs Unity account credentials, provided as secrets `UNITY_EMAIL` and
  `UNITY_PASSWORD` (add `UNITY_SERIAL` too if the account is Plus/Pro; a free Personal license
  needs no serial). Activate once per session before any other command:
  ```
  xvfb-run -a /opt/unity/Editor/Unity -batchmode -nographics -quit \
    -username "$UNITY_EMAIL" -password "$UNITY_PASSWORD" -logFile /dev/stdout
  ```
  (append `-serial "$UNITY_SERIAL"` for Plus/Pro). Alternatively use manual activation:
  `-createManualActivationFile` produces `Unity_v2020.3.16f1.alf`; upload it at
  https://license.unity3d.com/manual to get a `.ulf`, then activate with `-manualLicenseFile file.ulf`.

### Build / run / test (all require an active license)
- **Open/import + compile scripts (fastest sanity check):**
  `xvfb-run -a /opt/unity/Editor/Unity -batchmode -nographics -quit -projectPath /workspace -logFile /dev/stdout`
- **Run the game:** it is a mobile app, so "run" means either Editor Play Mode (launch the
  Editor GUI under `xvfb-run` and enter Play Mode) or a device/standalone build. There is no
  dev server and no ports.
- **Build:** done through the Editor (File → Build Settings) or `-buildTarget Android -executeMethod <BuildScript>`.
  Note: **no custom build script exists** in the repo, and **iOS builds require macOS/Xcode** so
  they are not possible on this Linux VM — Android/Linux-standalone are the feasible targets.
  Android signing keystore is at `/workspace/user.keystore`.
- **Lint:** none configured (only Rider/ReSharper inspection settings in
  `Assembly-CSharp.csproj.DotSettings`).
- **Tests:** the Unity Test Framework package is present but there are **no tests** in the repo
  (no `.asmdef` test assemblies). If added, run with `-runTests -testPlatform EditMode`.

### Notes
- The Windows `HintPath`s inside `Assembly-CSharp.csproj` are regenerated by the Editor on
  open; ignore them for Linux.
- `master` / tag `v1.1.1` is the production (Unity 2020) line; `develop` / `unity-upgrade-2023`
  are an incomplete Unity 2023 migration — do not treat those as production.
